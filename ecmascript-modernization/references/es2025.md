# ES2025 Modernization

Use TypeScript 6.0+ with `"target": "ES2025"` and `"lib": ["ES2025", ...]`.

## Iterator Helpers

Use iterator helpers for lazy pipelines where code currently spreads into arrays only to transform/filter a sequence.

Use this:

```ts
const activeNames = users
  .values()
  .filter((user) => user.active)
  .map((user) => user.name)
  .take(10)
  .toArray();
```

Not that:

```ts
const activeNames = Array.from(users.values())
  .filter((user) => user.active)
  .map((user) => user.name)
  .slice(0, 10);
```

Replaces:

- `Array.from(iterable).map(...)`
- `[...iterable].filter(...)`
- custom generator helpers such as `mapIter`, `filterIter`, `takeIter`
- eager utility-library chains over iterables when laziness matters

Use with care:

- Iterator helpers consume the iterator. Do not reuse the same iterator after a helper pipeline.
- Arrays still have better direct methods when the value is already an array and laziness is irrelevant.
- Async iterators are not covered by ES2025 synchronous iterator helpers.

## Set Methods

Use standard `Set` methods for common set algebra.

Use this:

```ts
const allowed = new Set(["read", "write"]);
const requested = new Set(["write", "delete"]);

const granted = allowed.intersection(requested);
const denied = requested.difference(allowed);
const hasOnlyAllowed = requested.isSubsetOf(allowed);
```

Not that:

```ts
const granted = new Set([...allowed].filter((item) => requested.has(item)));
const denied = new Set([...requested].filter((item) => !allowed.has(item)));
const hasOnlyAllowed = [...requested].every((item) => allowed.has(item));
```

Replaces:

- hand-written `union`, `intersect`, `difference`, and subset helpers
- spread/filter/every patterns for `Set`
- utility library helpers that only perform ordinary set algebra

Use with care:

- These methods return new `Set` instances and do not mutate the original set.
- Preserve custom ordering assumptions in tests; result order follows `Set` insertion semantics.

## JSON Modules And Import Attributes

Use import attributes for JSON module imports in ESM projects.

Use this:

```ts
import config from "./config.json" with { type: "json" };
```

Not that:

```ts
import config from "./config.json" assert { type: "json" };
```

Also prefer this over ad hoc file reads when the JSON is a static module dependency:

```ts
import packageJson from "../package.json" with { type: "json" };
```

Replaces:

- deprecated import assertions syntax
- `createRequire(import.meta.url)("./file.json")` in ESM when static import is acceptable
- `JSON.parse(readFileSync(...))` for static build/runtime metadata

Use with care:

- Keep dynamic file reads for user-supplied paths, runtime-generated files, or config that must be read after process start.
- Check bundler and runtime support. JSON module behavior is host-sensitive.
- TypeScript projects may still need `resolveJsonModule: true` depending on module settings and tooling.

## RegExp.escape

Use `RegExp.escape()` whenever user input or arbitrary strings become part of a regex pattern.

Use this:

```ts
const query = "a+b.txt";
const matcher = new RegExp(`^${RegExp.escape(query)}$`, "u");
```

Not that:

```ts
const query = "a+b.txt";
const matcher = new RegExp(`^${query.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")}$`, "u");
```

Replaces:

- local `escapeRegExp` helpers
- copy-pasted regex escaping snippets
- dependency utilities used only for regex escaping

Use with care:

- Do not use `RegExp.escape()` on complete regex syntax that intentionally contains operators.
- Escape only the literal fragment, then compose it with the surrounding regex syntax.

## Inline RegExp Modifiers

Use inline modifiers to scope regex flags to only part of a pattern.

Use this:

```ts
const matcher = /^(?i:todo|fixme):\s+(?-i:[A-Z][\w-]+)$/;
```

Not that:

```ts
const matcher = /^(todo|fixme):\s+([A-Z][\w-]+)$/i;
```

Replaces:

- global flags that accidentally affect the whole pattern
- splitting one logical regex into multiple regexes only to vary flags
- manual case normalization before matching when only one subpattern should be case-insensitive

Use with care:

- Inline modifiers are best when the scoped flag is obvious. If the regex becomes hard to read, keep separate named regexes.
- Verify tooling support in formatters, linters, minifiers, and test runtimes before broad use.

## Promise.try

Use `Promise.try()` to normalize sync-or-async callbacks into promise chains while capturing synchronous throws.

Use this:

```ts
return Promise.try(() => loadPlugin(pluginName))
  .then((plugin) => plugin.run(context))
  .catch((error) => reportPluginError(error));
```

Not that:

```ts
return Promise.resolve()
  .then(() => loadPlugin(pluginName))
  .then((plugin) => plugin.run(context))
  .catch((error) => reportPluginError(error));
```

Replaces:

- `Promise.resolve().then(fn)`
- hand-written `try/catch` wrappers that return rejected promises
- small `promiseTry` helper functions

Use with care:

- Use `await` and ordinary `try/catch` inside `async` functions when that is clearer.
- `Promise.try()` is most valuable at API boundaries that accept callbacks which may be sync or async.

## Float16Array And Float16 Helpers

Use Float16 APIs for compact numeric buffers and binary formats that specifically require IEEE 754 half precision.

Use this:

```ts
const samples = new Float16Array([0.1, 0.2, 0.3]);
const rounded = Math.f16round(0.33333);

const view = new DataView(new ArrayBuffer(2));
view.setFloat16(0, rounded, true);
const value = view.getFloat16(0, true);
```

Not that:

```ts
const samples = new Float32Array([0.1, 0.2, 0.3]);
const rounded = customFloat16Round(0.33333);
```

Replaces:

- custom half-float encode/decode helpers
- using `Float32Array` where a file format, GPU pipeline, ML model, or binary protocol requires float16
- third-party half-precision helpers when no special compatibility behavior is needed

Use with care:

- Do not switch ordinary numeric business logic to float16. Precision loss is the point of the format.
- Keep `Float32Array` or `Float64Array` for general computation unless storage or protocol compatibility requires float16.
