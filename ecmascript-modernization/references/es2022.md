# ES2022 Modernization

Use `"target": "ES2022"` and `"lib": ["ES2022", ...]` or newer. ES2022 is a strong modern baseline for classes, top-level await, error causes, and ergonomic object checks.

## Class Fields And Private Fields

Use public class fields and private fields for class-owned state.

Use this:

```ts
class Counter {
  #count = 0;
  label = "Counter";

  increment() {
    this.#count += 1;
  }
}
```

Not that:

```ts
class Counter {
  constructor() {
    this._count = 0;
    this.label = "Counter";
  }

  increment() {
    this._count += 1;
  }
}
```

Replaces:

- constructor assignments for simple fields
- underscore "private by convention" properties
- WeakMap-based private state in ordinary classes

Use with care:

- `#private` fields are runtime-private and cannot be accessed by tests or subclasses.
- Keep TypeScript `private` when compile-time-only privacy is enough and the codebase relies on structural testing or subclass access.

## Private Field Checks

Use `#field in value` to brand-check class instances.

Use this:

```ts
class Token {
  #value: string;

  static isToken(value: unknown): value is Token {
    return typeof value === "object" && value !== null && #value in value;
  }
}
```

Not that:

```ts
value instanceof Token
```

Replaces:

- `instanceof` checks when private-field branding is the actual invariant

Use with care:

- `instanceof` is still clearer for ordinary same-realm class checks.

## Top-Level await

Use top-level `await` in ESM modules for startup dependencies.

Use this:

```ts
const config = await loadConfig();

export const app = createApp(config);
```

Not that:

```ts
export const appPromise = loadConfig().then((config) => createApp(config));
```

Replaces:

- exported promise wrappers for module initialization
- immediately invoked async functions around module setup

Use with care:

- Top-level await can delay module graph evaluation.
- Avoid it in library entrypoints unless the package explicitly supports async module initialization.

## Error cause

Use `Error` `cause` to preserve original failure context.

Use this:

```ts
throw new Error("Failed to load config", { cause: error });
```

Not that:

```ts
const nextError = new Error(`Failed to load config: ${String(error)}`);
throw nextError;
```

Replaces:

- string-concatenated error wrapping
- custom `originalError` properties

Use with care:

- Ensure logging/reporting tools display `cause`.
- Do not expose sensitive lower-level error details to users.

## Object.hasOwn

Use `Object.hasOwn()` for own-property checks.

Use this:

```ts
if (Object.hasOwn(config, key)) {
  apply(config[key]);
}
```

Not that:

```ts
if (Object.prototype.hasOwnProperty.call(config, key)) {
  apply(config[key]);
}
```

Replaces:

- verbose `hasOwnProperty.call(...)`
- unsafe `obj.hasOwnProperty(key)` calls

Use with care:

- Use `key in obj` when inherited properties should count.

## Array, String, And TypedArray .at

Use `.at()` for relative indexing, especially the last item.

Use this:

```ts
const lastMessage = messages.at(-1);
```

Not that:

```ts
const lastMessage = messages[messages.length - 1];
```

Replaces:

- `array[array.length - 1]`
- `string[string.length - 1]`

Use with care:

- Bracket indexing is still best for simple non-negative indexes.

## RegExp Match Indices

Use the `d` flag when match start/end positions matter.

Use this:

```ts
const match = /name=(?<name>\w+)/d.exec(input);
const range = match?.indices?.groups?.name;
```

Not that:

```ts
const match = /name=(\w+)/.exec(input);
const start = match ? input.indexOf(match[1]) : -1;
```

Replaces:

- fragile `indexOf()` math after regex matching

Use with care:

- Only use `d` when indices are actually needed; it adds visual noise.
