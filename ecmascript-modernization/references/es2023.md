# ES2023 Modernization

Use TypeScript 5.0+ with `"target": "ES2023"` and `"lib": ["ES2023", ...]`.

## Copy-On-Write Array Methods

Use copy-on-write array methods when code currently clones an array only to mutate the clone.

Use this:

```ts
const sortedUsers = users.toSorted((a, b) => a.name.localeCompare(b.name));
const reversedItems = items.toReversed();
const nextSteps = steps.toSpliced(index, 1, replacement);
const updated = values.with(2, "done");
```

Not that:

```ts
const sortedUsers = [...users].sort((a, b) => a.name.localeCompare(b.name));
const reversedItems = [...items].reverse();

const nextSteps = [...steps];
nextSteps.splice(index, 1, replacement);

const updated = [...values];
updated[2] = "done";
```

Replaces:

- spread-then-`sort`, spread-then-`reverse`, and clone-then-`splice`
- immutable update helpers for simple array replacement
- accidental mutation of input arrays

Use with care:

- `toSorted()`, `toReversed()`, `toSpliced()`, and `with()` return new arrays and leave the original untouched.
- Keep mutating methods when in-place mutation is intentional and observable.
- These methods also exist for typed arrays where supported.

## findLast And findLastIndex

Use `findLast()` and `findLastIndex()` when searching from the end of an array.

Use this:

```ts
const latestFailure = runs.findLast((run) => run.status === "failed");
const latestFailureIndex = runs.findLastIndex((run) => run.status === "failed");
```

Not that:

```ts
const latestFailure = [...runs].reverse().find((run) => run.status === "failed");

let latestFailureIndex = -1;
for (let index = runs.length - 1; index >= 0; index -= 1) {
  if (runs[index].status === "failed") {
    latestFailureIndex = index;
    break;
  }
}
```

Replaces:

- clone-reverse-find patterns
- manual reverse loops for ordinary last-match searches
- utility helpers such as `findLast(array, predicate)`

Use with care:

- `findLast()` returns the element; `findLastIndex()` returns the index or `-1`.
- The original array is not reversed or mutated.

## Symbols As WeakMap Keys

Use non-registered symbols as `WeakMap` keys when symbol identity is the correct weakly held key.

Use this:

```ts
const cache = new WeakMap<symbol, Metadata>();
const token = Symbol("plugin");

cache.set(token, { loaded: true });
```

Not that:

```ts
const cache = new WeakMap<object, Metadata>();
const token = { description: "plugin" };

cache.set(token, { loaded: true });
```

Replaces:

- wrapper objects created only to serve as `WeakMap` keys
- awkward identity-token objects when a unique symbol communicates intent better

Use with care:

- Registered symbols from `Symbol.for()` are not valid weak keys because they are globally reachable.
- Use object keys when the object lifecycle is what should control cache lifetime.

## Hashbang Grammar

Use standardized hashbang syntax for executable JavaScript entrypoints.

Use this:

```js
#!/usr/bin/env node

import { main } from "./main.js";

await main(process.argv.slice(2));
```

Not that:

```js
// Run this file with: node ./cli.js
import { main } from "./main.js";

await main(process.argv.slice(2));
```

Replaces:

- build-tool-specific hashbang stripping assumptions
- separate shell wrapper scripts for simple Node CLIs

Use with care:

- The hashbang must be the first line of the file.
- Keep package `bin` metadata and executable file permissions aligned.
