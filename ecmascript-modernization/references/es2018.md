# ES2018 Modernization

Use `"target": "ES2018"` and `"lib": ["ES2018", ...]` or newer. ES2018 is useful for object rest/spread, async iteration, `finally()`, and stronger regular expressions.

## Object Rest And Spread

Use object spread for shallow object copies and rest for excluding properties.

Use this:

```ts
const nextUser = { ...user, name: "Ada" };
const { passwordHash, ...publicUser } = user;
```

Not that:

```ts
const nextUser = Object.assign({}, user, { name: "Ada" });

const publicUser = { ...user };
delete publicUser.passwordHash;
```

Replaces:

- `Object.assign({}, value, patch)` for simple immutable updates
- clone-then-`delete` for omitting fields
- local `omit()` helpers for one-off exclusions

Use with care:

- Spread is shallow. Keep structured cloning or explicit mapping for nested data.
- Rest/spread only copies enumerable own properties.

## Promise.prototype.finally

Use `finally()` for cleanup that must run after success or failure.

Use this:

```ts
spinner.start();

return runTask()
  .finally(() => {
    spinner.stop();
  });
```

Not that:

```ts
spinner.start();

return runTask()
  .then((value) => {
    spinner.stop();
    return value;
  })
  .catch((error) => {
    spinner.stop();
    throw error;
  });
```

Replaces:

- duplicated cleanup in `.then()` and `.catch()`
- promise chains that obscure the actual success value

Use with care:

- Do not return a replacement success value from `finally()`. Use `then()` if cleanup changes the value.
- In `async` functions, ordinary `try/finally` may be clearer.

## Async Iteration

Use `for await...of` for async streams and async iterables.

Use this:

```ts
for await (const chunk of stream) {
  await writeChunk(chunk);
}
```

Not that:

```ts
stream.on("data", async (chunk) => {
  await writeChunk(chunk);
});
```

Replaces:

- event handlers that accidentally ignore backpressure
- manual async iterator `.next()` loops

Use with care:

- Only use this for async iterables. Some event emitters are not async iterables without an adapter.
- Understand cancellation and cleanup behavior for the source.

## RegExp Named Capture Groups

Use named capture groups when match indexes are hard to read.

Use this:

```ts
const match = /^(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})$/.exec(date);
const year = match?.groups?.year;
```

Not that:

```ts
const match = /^(\d{4})-(\d{2})-(\d{2})$/.exec(date);
const year = match?.[1];
```

Replaces:

- magic numeric capture indexes in non-trivial regexes

Use with care:

- Keep unnamed groups for tiny obvious regexes where names add noise.

## RegExp s Flag

Use the `s` flag when `.` should match newlines.

Use this:

```ts
const body = /<body>(?<content>.*)<\/body>/s.exec(html)?.groups?.content;
```

Not that:

```ts
const body = /<body>([\s\S]*)<\/body>/.exec(html)?.[1];
```

Replaces:

- `[\s\S]` and `[^]` dot-all hacks

Use with care:

- Avoid regex parsing for complex HTML, XML, or programming languages.
