# ES2024 Modernization

Use TypeScript 5.7+ with `"target": "ES2024"` and `"lib": ["ES2024", ...]`.

## Object.groupBy

Use `Object.groupBy()` when grouping iterable values by string or symbol keys and the result should be a plain object-like lookup.

Use this:

```ts
const usersByRole = Object.groupBy(users, (user) => user.role);
```

Not that:

```ts
const usersByRole = users.reduce<Record<string, User[]>>((groups, user) => {
  (groups[user.role] ??= []).push(user);
  return groups;
}, {});
```

Replaces:

- `reduce()` group-by boilerplate
- local `groupByObject` helpers
- utility library grouping when keys are strings or symbols and an object result is desired

Use with care:

- `Object.groupBy()` returns a null-prototype object. Avoid code that assumes methods such as `hasOwnProperty` exist on the result.
- Callback return values are coerced to property keys. Use `Map.groupBy()` for object keys or other non-string identity-sensitive keys.

## Map.groupBy

Use `Map.groupBy()` when grouping values by keys that should keep their original identity.

Use this:

```ts
const usersByTeam = Map.groupBy(users, (user) => user.team);
```

Not that:

```ts
const usersByTeam = new Map<Team, User[]>();

for (const user of users) {
  const group = usersByTeam.get(user.team);

  if (group) {
    group.push(user);
  } else {
    usersByTeam.set(user.team, [user]);
  }
}
```

Replaces:

- hand-written `Map` accumulation loops
- object grouping that stringifies object keys as `"[object Object]"`
- utility library grouping when callers need `Map` methods or non-string keys

Use with care:

- `Map.groupBy()` groups by key identity. Two distinct object instances with the same shape are different keys.
- Prefer `Object.groupBy()` when the consumer expects JSON-like object output.

## Promise.withResolvers

Use `Promise.withResolvers()` when code needs a promise and its `resolve`/`reject` functions as separate values.

Use this:

```ts
const { promise, resolve, reject } = Promise.withResolvers<Result>();

queue.push({ resolve, reject });

return promise;
```

Not that:

```ts
let resolve!: (value: Result) => void;
let reject!: (error: unknown) => void;

const promise = new Promise<Result>((res, rej) => {
  resolve = res;
  reject = rej;
});

queue.push({ resolve, reject });

return promise;
```

Replaces:

- deferred-promise constructor boilerplate
- local `deferred()` or `createDeferred()` helpers
- mutable outer `resolve`/`reject` variables with definite-assignment assertions

Use with care:

- Prefer ordinary `async` functions when there is no real need to resolve a promise from outside the executor.
- Keep ownership clear. Exposing `resolve` and `reject` widely can make async flows harder to reason about.

## RegExp v Flag

Use the `/v` flag for Unicode set notation, string properties, nested character classes, intersection, and subtraction.

Use this:

```ts
const asciiLetter = /[\p{Letter}&&\p{ASCII}]/v;
const nonAsciiLetter = /[\p{Letter}--\p{ASCII}]/v;
```

Not that:

```ts
const asciiLetter = /[A-Za-z]/u;
const nonAsciiLetter = /\p{Letter}/u;
```

Replaces:

- brittle manually maintained Unicode ranges
- multi-step regex checks for character-class intersection or subtraction
- custom validation helpers for Unicode-aware string matching

Use with care:

- `/v` is not a drop-in replacement for `/u`; test patterns carefully.
- Verify that linters, minifiers, and test runtimes understand `/v` syntax before broad use.

## Well-Formed Unicode Strings

Use `String.prototype.isWellFormed()` and `String.prototype.toWellFormed()` when data may contain lone surrogate code units.

Use this:

```ts
if (!input.isWellFormed()) {
  input = input.toWellFormed();
}
```

Not that:

```ts
input = input.replace(
  /[\uD800-\uDBFF](?![\uDC00-\uDFFF])|(?<![\uD800-\uDBFF])[\uDC00-\uDFFF]/g,
  "\uFFFD",
);
```

Replaces:

- custom lone-surrogate detection helpers
- fragile regular expressions for Unicode repair
- encoding preflight logic before passing strings to APIs that require valid Unicode scalar values

Use with care:

- `toWellFormed()` replaces invalid surrogates with the replacement character. Do not use it when exact original code units must be preserved.
- Keep explicit validation errors when invalid Unicode should reject the input instead of repairing it.

## Atomics.waitAsync

Use `Atomics.waitAsync()` for non-blocking waits on shared memory in worker or multithreaded runtimes.

Use this:

```ts
const result = await Atomics.waitAsync(sharedArray, 0, 0).value;
```

Not that:

```ts
const result = Atomics.wait(sharedArray, 0, 0);
```

Replaces:

- blocking `Atomics.wait()` in contexts that must stay responsive
- polling loops over `SharedArrayBuffer` state
- ad hoc message-channel coordination when shared-memory waiting is the right primitive

Use with care:

- This is specialized concurrency code. Avoid it in ordinary application flow.
- The typed array must be backed by a `SharedArrayBuffer`, and the environment must support shared memory.

## Resizable And Transferable Buffers

Use resizable buffers when binary data grows over time and copying into new buffers is a measurable cost. Use transfer APIs when ownership should move to a new buffer and the old buffer should detach.

Use this:

```ts
const buffer = new ArrayBuffer(8, { maxByteLength: 16 });

if (buffer.resizable) {
  buffer.resize(12);
}

const transferred = buffer.transfer();
```

Not that:

```ts
let buffer = new ArrayBuffer(8);
const next = new ArrayBuffer(12);

new Uint8Array(next).set(new Uint8Array(buffer));
buffer = next;
```

Replaces:

- manual allocate-copy-reassign growth for `ArrayBuffer`
- custom binary buffer growth helpers
- clone-then-ignore patterns for handoff

Use with care:

- Check `resizable`, `maxByteLength`, and view behavior before resizing. Existing typed-array views may change length or become out of bounds.
- Transferring detaches the original buffer. Do not transfer if existing readers still need the old buffer.
